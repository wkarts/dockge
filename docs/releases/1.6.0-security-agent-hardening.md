# Dockge 1.6.0 — Security, Automation API & Infrastructure Agent Hardening

Esta promoção consolida a primeira linha independente/API-first com endurecimento de segurança humana, automação de infraestrutura e fechamento do ciclo Control Plane → Agent → Dockge → Docker/Compose.

## Incluído

- TOTP/2FA com segredo protegido por AES-256-GCM e invalidação de sessões por `auth_revision`;
- API Access administrável pela interface, com credenciais de uso único, SHA-256, scopes, expiração e namespaces de stacks;
- REST API de automação sem shell remoto arbitrário;
- atualização de stack sem apagar `.env` quando `compose_env` é omitido;
- gravação atômica/privada de `.env`, ownership e store de idempotência;
- idempotência persistente nas mutações `PUT`, `DELETE` e ações Docker Compose via `Idempotency-Key`;
- replay seguro de ações concluídas e bloqueio fail-closed (`idempotency_result_in_doubt`) na janela de crash indeterminado;
- Generic Infrastructure Agent **0.2.0**, multi-Control-Plane, com credenciais por vínculo, journal local e idempotência ponta a ponta usando `action.id`;
- validação explícita de HTTPS/HTTP e bloqueio de esquemas inválidos;
- rejeição de reutilização de arquivos de credencial/identidade entre Control Planes;
- reconfiguração case-insensitive do mesmo vínculo sem duplicar identidades;
- Windows Service nativo, Linux systemd e macOS LaunchDaemon;
- pipelines para binários e instaladores Linux/Windows/macOS;
- descoberta/coexistência com Docker e Dockge existentes, sem remoção ou adoção automática;
- Dockerfile autocontido e imagens oficiais direcionadas a `ghcr.io/wkarts/dockge`;
- correção da classificação de `ValidationError` nos sockets e HTTP 400 na API para validações de stack;
- separação definitiva das regras comerciais: licenciamento, inadimplência, aprovação de upgrade e backup pertencem ao Control Plane consumidor.

## Git Flow

- `develop`: integração/homologação;
- `main`: produção estável;
- canal GHCR de homologação: `:develop` / `:develop-<sha>`;
- release estável planejada pelo workflow SemVer em `main`.

## Versionamento do Agent

O Generic Infrastructure Agent possui ciclo próprio. Esta linha prepara `infrastructure-agent/VERSION = 0.2.0`; a publicação estável deve ocorrer pelo workflow `60 · Agent Release` a partir de `main`, gerando a tag `infrastructure-agent-v0.2.0` e os pacotes Linux, Windows e macOS.

## Observação operacional

A versão `1.6.0` é o próximo SemVer planejado a partir do `VERSION` atual `1.5.0`. A tag, GitHub Release e imagem estável somente devem ser consideradas publicadas quando o workflow `50 · Release SemVer` em `main` concluir com sucesso. Da mesma forma, o Agent 0.2.0 somente é release estável após a execução confirmada do workflow específico do Agent.
